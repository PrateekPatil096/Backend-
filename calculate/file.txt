3. What are the Tradeoffs Inherent in Handheld Computers? 6–7 MARKS
Handheld computing architectures require balances between portable form factors and operational capabilities:
Processing Performance vs. Battery Life: High-frequency processors increase responsiveness but accelerate battery drain
and heat generation. Handheld CPUs run at conservative clock speeds with dynamic frequency scaling.
Physical Memory vs. Storage Paging: Handheld devices have limited RAM and generally avoid traditional virtual memory
paging to flash storage. Flash media has finite write endurance, and aggressive paging wears out storage while drawing
significant battery power.
Screen Size vs. User Interface: Small screens limit visible workspace. OS designs must rely on streamlined single-window
interfaces and responsive layouts rather than multi-window desktop metaphors.
Thermal Dissipation Constraints: Without fans, handhelds depend on passive heat dissipation, requiring thermal throttling
during sustained workloads to avoid overheating.

Q15. OS Security on Systems without Hardware Privileged Mode: Is It Possible? 6–7 MARKS
When computer hardware lacks a privileged mode, boundary enforcement shifts entirely to software:
Arguments that It IS Possible
Software Sandboxing / Interpreters: Applications run
inside an interpreter or virtual execution environment
(e.g., JVM). The engine validates bytecodes and memory
accesses before execution.
Type-Safe Languages: If software is authored exclusively
in languages that prevent raw pointer arithmetic and
enforce strict type safety (e.g., Java, Rust)
, compilers can
eliminate invalid memory accesses.
Software Fault Isolation (SFI): Compilers can insert inline
validation instructions before every load, store, or jump to
verify memory bounds without dedicated hardware
support.
Arguments that It is NOT Possible
Unchecked Native Code: If users run arbitrary machine
binaries, the CPU will execute raw instructions without
bounds checks, allowing processes to overwrite OS code
or access devices directly.
Vulnerability to Modified Binaries: A malicious actor can
bypass compiler restrictions by patching instructions at
the binary level, executing instructions that software
checks cannot intercept.
Conclusion: Secure operation is possible only within a
strictly closed, verified language sandbox. It is impossible
if the system permits arbitrary native binary execution.

Q18. Clustered Systems vs. Multiprocessor Systems & High Availability. 6–7 MARKS
Multiprocessor systems are tightly coupled: multiple CPUs share a bus, memory, and peripheral devices inside a single
chassis. Clustered systems are loosely coupled: two or more independent, networked computers share storage resources (via
a SAN) and software coordination.
Heartbeat Interconnect: Cluster nodes continuously exchange heartbeat signals over dedicated network paths to detect host
failures immediately.
Shared Storage (SAN / NAS): Shared storage allows surviving nodes to access data disks and recover active application
states after a node failure.
Distributed Lock Management (DLM): Synchronizes concurrent file operations to ensure only one host writes to shared
volumes at a time.
Failover Middleware: Automatically shifts virtual IP addresses and restarts services on surviving nodes during a failover event.
Q19. Writing an Operating System for a Real-Time Environment (RTOS). 6–7 MARKS
The primary challenge in writing an RTOS is guaranteeing strict temporal determinism. System correctness depends not only
on producing accurate computational results, but on delivering them before strict deadlines.
Bounding Latencies: The kernel must minimize and strictly bound both Interrupt Latency (time from hardware interrupt arrival
to ISR execution) and Dispatch Latency (time needed to stop the running task and context-switch to a higher-priority task).
Preemptive Kernel Design: The kernel must support preemption during system calls. Long critical sections that disable
interrupts must be replaced with fine-grained locking or priority-aware synchronization.
Resolving Priority Inversion: When a lower-priority task holds a resource needed by a high-priority task, middle-priority tasks
can preempt the low-priority task, causing an unbounded delay. The RTOS must implement Priority Inheritance Protocols to
prevent this condition.
Avoiding Non-Deterministic Behaviors: Traditional virtual memory paging to secondary storage introduces unpredictable
delays and must be avoided; memory allocations must be static or time-bounded.
